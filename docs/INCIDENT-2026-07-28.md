# Incident review — 28 Jul 2026

Two defects were found in the live paper-trading engine on the same day. Both had
been live for weeks. This is the write-up: what broke, how it was found, what it
cost, and what changed. Numbers here are checkable via
[`VERIFY.md`](VERIFY.md) C8–C10; the canonical ledger is [`RESULTS.md`](RESULTS.md).

---

## Defect A — exit recording stopped (22 Jul → 28 Jul)

A position-sizing deploy on 22 Jul over-indented the trade-recording block into
the `elif new_bar:` (max-hold) branch of the basket engine's exit loop.

The exit conditions are checked in precedence order — stop-loss, MACD cross-down,
bearish divergence, then max-hold. Because the recorder now sat *inside* the last
branch, the first three set a reason and then fell straight through it: those
exits stopped being recorded at all. Worse, the line that closed the position
(`del d["open"][stock]`) sat *outside* the `if reason and px:` guard, so any
position reaching that branch was dropped whether or not a trade had been
written.

**Cost:** 62 positions were deleted with no trade recorded (19 on 23 Jul, 21 on
24 Jul, 20 on 27 Jul, 2 on 28 Jul). Every exit recorded after 22 Jul is a
max-hold — the only path that still reached the recorder. The record for that
window is therefore both incomplete and biased.

**How it was found:** the exit-reason distribution. Before 22 Jul the record
showed a healthy mix (MACD Cross 92, Stop Loss 33, Max Hold 63); after, it showed
max-hold and nothing else. Comparing the count of equity-curve appends against
the count of recorded trades per day exposed the 62 silent deletions.

**Uncomfortable detail:** four existing unit tests — stop-loss close, cross-down
close, freed-slot reuse, total-P&L — were *already failing* on the branch that
shipped. They were not run. The fix adds a regression test that fails against the
old code and passes against the new.

## Defect B — the divergence filter had never run (11 Jun → 28 Jul)

Both live engines built the V2 divergence detector's input frame from bare NumPy
arrays, giving it a `RangeIndex`. The detector formats `df.index[...]` with
`.strftime()` when it builds an event row. So every call that actually found a
divergence raised `AttributeError` — and a blanket `except Exception: return
"none"` turned that into a clean-looking "no divergence".

The filter was wired in, documented as active, and dead from the day V2 shipped.

**Measurement** (89 stocks × 23 hourly bars, 23–28 Jul):

```
before fix:  none 2047 / 2047 (100%)        77 cross-ups,  0 blocked
after  fix:  none 48.4% · bearish 30.8%     77 cross-ups, 25 blocked (32.5%)
                        · bullish 20.8%
```

**Why it matters more than defect A:** `STRATEGY.md` calls the bearish-divergence
exit *the profit engine* and the MACD cross-back *the loss-cutter*. With the
profit engine absent, positions had no way to take profit — they ran until either
momentum had already died or the stop was hit. The backtest that produced Sharpe
2.998 has the filter **on**. So for seven weeks the live engine was running a
materially different strategy from the one that was validated.

## What the forward record actually says

Clean window, 22 Jun – 22 Jul, archived at
`archive/basket_forward_20260622_20260722.json`:

| Exit reason | Trades | P&L | WR | Avg |
|---|--:|--:|--:|--:|
| Stop Loss | 35 | **−₹31,395** | 0.0% | −2.69% |
| MACD Cross | 105 | **−₹16,845** | 21.0% | −0.48% |
| Max Hold | 63 | **+₹22,243** | 65.1% | +1.06% |
| **Total** | **203** | **−₹25,997** | **31.0%** | |

−5.20% of the ₹5,00,000 paper pool. Two things worth reading carefully:

- **Max-hold is the only green bucket, and that is not an endorsement of holding
  longer.** Exit precedence means a trade only *reaches* max-hold if it never fell
  2% and never lost its MACD — it is the residual of trades that were already
  working. Extending max-hold would not manufacture more of them.
- **Stop-loss exits averaged −2.69% against a 2.0% stop.** The engine checks the
  stop on 15-minute closes, never intrabar, so gaps and fast moves slip through
  it. That is ~0.7pp of avoidable loss on 35 trades, and it is a real
  implementation cost the backtest does not model.

### Counterfactual: how much was defect B worth?

Replaying each archived trade's holding window and exiting at the first bar its
divergence state would have turned bearish (historical bars, live `recency=15`):

| Bucket | Div fires first | Actual Σ pnl_pct | With div-exit | Δ |
|---|--:|--:|--:|--:|
| MACD Cross (105) | 72 (69%) | −50.55% | −14.76% | **+35.8 pp** |
| Stop Loss (35) | 25 (71%) | −94.20% | −40.26% | **+53.9 pp** |
| Max Hold (63) | 51 (81%) | +66.73% | +18.35% | **−48.4 pp** |
| **Whole record** | | **−78.02%** | **−36.67%** | **+41.4 pp** |

Win rate 31.0% → 38.9%. The filter rescues the losers hard — on 24 of the 25
stop-loss trades it exits *before* the stop, so the gap-through cost never
happens — and it clips the winners, better in only 21 of 51 max-hold trades.

**The honest conclusion: the missing filter explains roughly half the loss, not
all of it.** With it, the record would still have been negative. That remaining
gap is not yet fully accounted for.

*Caveats: this is a counterfactual on historical bars, not a forward result.
Trades are matched to bars by date, and it ignores knock-on effects — an earlier
exit frees a slot, changes later entries, and changes the consecutive-loss counter
and therefore sizing. Directionally sound, not exact.*

## What changed

- Both defects fixed, tested (19 passing) and deployed the same day.
- Divergence detector failures now **log instead of silently degrading to
  `"none"`**. A permanently-failing detector is indistinguishable from "no
  signal", and that is precisely how this hid for seven weeks.
- The clean forward window and the reconstruction of the corrupted window are
  **archived, not deleted** — both ship in this repo.
- The forward paper record **restarted 28 Jul 2026** on the fixed engine, with
  the divergence filter live for the first time. The ~3-month money-gate clock
  restarts with it. Real capital deployed: still **zero**.

## Still open

1. **`div_recency` is 15 in the live feed, 6 in the tuned strategy** and in
   `STRATEGY.md`. This only began to matter on 28 Jul — before the fix the filter
   never ran at all. A wider window blocks more entries.
2. **Max-hold is counted in calendar days live, in bars in the backtest.** Live
   uses `(today - entry_date).days >= 3`; the backtest uses 75 × 15m bars = 3
   *trading* days. 45 of 63 archived max-hold exits fired with fewer than 3
   trading days held, mostly Thursday/Friday entries.
3. **Stop-loss slippage** — whether to model it, or check the stop more often.
4. **The decay gate's flags are stale** (frozen 21 Jun; 29 of 90 names benched on
   5-week-old trailing returns). Recomputing needs deeper per-stock history than
   the free data source provides.
5. **`yfinance` is unpinned**, and its timezone behaviour changed bar labels
   mid-record — one build returns UTC, another returns `Asia/Kolkata`. The
   archived record contains both conventions, which added noise to new-bar
   detection and day counting. Pin it.
