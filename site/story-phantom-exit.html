The phantom exit

How the most important rule of a live strategy silently did nothing for six weeks — and how a trade that could not exist finally exposed it.

The setup

My basket engine's exit stack had a "profit engine": exit longs when a bearish divergence appears (price making highs the momentum doesn't confirm). The backtest loved it. The engine was deployed, the record was running, life was good.

The symptom

The forward record bled for a month: 203 trades, 31% win-rate, meaningfully negative. The exit breakdown was strange — not a single divergence exit had ever fired. Positions only ever left through the stop-loss, the cross-back, or max-hold. The profit engine was a ghost.

The cause

The divergence detector formatted timestamps from the dataframe index. The live path built that frame from bare arrays — so the index was integers. Every call raised an AttributeError… which a blanket except: return "none" swallowed. For six weeks, on every bar, for every stock, the answer was silently "no divergence."

The live engine was not running the strategy that was backtested. It was running the backtested strategy minus its most important rule — and nothing, anywhere, said so.

The counterfactual

I replayed every archived trade's holding window asking: "where would the divergence exit have fired?" Answer: it would have rescued roughly half the bleed — it fired before the stop-loss in 24 of 25 stop-outs. The other half of the bleed was real strategy weakness. Both facts mattered; neither was visible before the forensics.

The phantom

Then the twist. One closed trade in the record showed exit reason "Bearish Div" — dated during the broken era, when that exit was provably impossible. No live code path could have produced it. The lead: a seeding script had rewritten exit reasons on old trades. A record you can't trust is worse than no record at all.

What changed

  • Audit trail: every exit now stores a snapshot of the signal that caused it. A trade can never be unexplainable again.
  • Exceptions may not fail silent in a live signal path. A rule that errors must scream, not shrug.
  • "Deployed" ≠ "running". I now verify that each rule actually fires in production, not just that the code shipped.
  • Celebration comes after verification. Always. I got this wrong more than once; it's expensive every time.
