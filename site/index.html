The pipeline every idea goes through

hypothesis │ ▼ pre-register the rules ──► git commit (timestamped, BEFORE any simulation) │ ▼ iterate on TRAIN data only test period stays sealed in code │ ▼ declare champion ──► ONE sealed test look ──► verdict per the pre-written rule │ │ │ pass │ fail ▼ ▼ 4-week PAPER gate (live, fees-net, audited) graveyard ✝ (logged, never tweaked) │ pass ▼ only then: a real-money conversation

Four rules we don't break

  • 1. The verdict is written before the test. Champion rules and pass/fail thresholds are committed to git before a single simulation runs. No moving goalposts.
  • 2. One sealed look. The out-of-sample period is hidden by the tooling itself. It gets opened once, for the declared champion. Fail → closed forever, no post-test tweaks.
  • 3. Costs on every trade, every time. A backtest without fees is fiction. We learned this the hard way — a "Sharpe 2.31" strategy of ours turned out to be net-negative in the current year once costs were counted. It's in the graveyard now.
  • 4. Failures get published. The rejection log is the moat. 41 documented deaths protect the few things that survive.

Why believe any of this?

Because it's checkable. The research log — including the pre-registration commits, the rejection ledger and the harness code that reproduces our headline claims — is public on GitHub. The live experiment page updates weekly with the paper record versus what the backtest predicted — including the weeks where they disagree.

The most impressive thing about a strategy is not its returns. It's whether the research process was designed to challenge it.
